## [HIGH] firebase/functions/src/routes/webhooks.js:181

**Transient Fakturownia failure permanently loses the VAT invoice — the reservation release relies on a Stripe retry that never comes**

- Scenariusz: Klient B2B placi (checkout.session.completed). obsluzCheckout aktywuje tier (sukces) i wola wystawFakture. Fakturownia jest skonfigurowana, ale ma chwilowy blip: zwraca HTTP 500 albo timeout -> createStandardInvoice zwraca {created:false, error:'HTTP 500'} (NIE rzuca). wystawFakture zwalnia rezerwacje faktury (faktury.zwolnij) i loguje ERROR, ALE nie rzuca. obsluzCheckout konczy sie normalnie, markDone(event.id) sie udaje, webhook odpowiada 200. Efekt: faktura VAT znika bezpowrotnie po jednym chwilowym bledzie Fakturowni, jedyny slad to jeden wpis ERROR, brak jakiejkolwiek automatycznej naprawy. zwolnij() pomaga wylacznie hipotetycznemu recznemu re-runowi, ktorego nikt nie odpala.
- Naprawa: Rozroznic blad TRWALY/degradacje (nie retryowac) od bledu PRZEJSCIOWEGO (HTTP 5xx / timeout). Albo dolozyc wlasna kolejke ponowien faktur zamiast polegac na Stripe.

## [HIGH] firebase/functions/src/routes/webhooks.js:181

**Transient Fakturownia failure permanently drops the VAT invoice — reservation release enables no retry because the webhook already returned 200**

- Scenariusz: Paying B2B customer completes checkout with Fakturownia ENABLED. createStandardInvoice hits a transient error (HTTP 500 / network timeout / AbortSignal 20s) and returns {created:false, error:...}. wystawFakture releases the invoices/{session.id} reservation (line 181) and logs ERROR. But wystawFakture never throws, so obsluzCheckout completes normally, handleEvent returns, markDone runs, and the webhook responds 200 (line 74). Stripe considers the event delivered and does NOT retry. There is no invoice-retry cron anywhere in src/. Result: the reservation is released but nothing ever re-invokes wystawFakture — the customer is charged, activated, and never receives a legally-required faktura VAT. The code comment (lines 177-183) claims release enables 'ponowienie Stripe albo ręczne wywołanie', but Stripe retry is impossible after a 200, so the release is purely a no-op that guarantees the invoice is lost rather than protected.
- Naprawa: Distinguish transient failure (created:false with error) from configured-off degradation (degraded:true). For a transient failure, throw out of obsluzCheckout so the webhook returns 500 and Stripe redelivers (setTier is idempotent, reservation already released so the invoice re-issues). Only the degraded case should return 200 without retry. Alternatively enqueue the session for a dedicated invoice-retry job.
